# writing-guidelines

適用 README、MCP 工具說明、Plugin 介面、工作交接與診斷訊息。原始碼註解應就近描述契約和失敗原因；不要把工程說明直接堆進 Chrome 可見畫面，也不為了整齊把必要錯誤提示隱藏。

文件分別標示已做／有測試／部署完成／正式功能驗證，避免「可使用」等無證據宣稱。產品統一寫 LAS 或 LunArcus，六個模組嚴格按 `AGENTS.md` 職責。需要外部編寫規範時按需參考 https://raw.githubusercontent.com/vercel-labs/writing-guidelines/main/command.md ，不開機自動抓取。
